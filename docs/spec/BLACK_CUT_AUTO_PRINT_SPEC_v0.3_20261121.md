## 1. 目的・利用シーン

### 1.1 解決する問題

A4未満の本・冊子・教材などを複合機の原稿台でスキャンすると、紙面周辺の原稿台が黒または暗灰色として取り込まれ、普通のコピー機能の背景除去では黒い領域が印刷される場合がある。これを、スキャン後にPCの画像編集ソフトで加工する手間なく、自動的に処理してA4の白黒印刷物として出力したい。

### 1.2 目標操作

1. Windowsで「黒カット印刷」を起動し、監視を**ON**にしておく。
2. MF244dwの原稿台に本を置く。
3. 複合機本体の **［コピー/スキャン］→［スキャン］→［PC］→スキャン種別選択→［スタート/確定］** に相当する操作でスキャンする。実際の操作表示は現行の本体設定に従う。
4. Canon MF Scan Utilityが、スキャン結果をPCの専用受信フォルダに保存する。
5. 常駐アプリが新規ファイルを検出し、**上下左右を問わず紙面外側の黒・暗灰色領域だけを除く**。
6. 紙面をA4の印刷可能領域に配置し、MF244dwへ**確認ダイアログなしで1部、片面、白黒**の印刷ジョブを送信する。
7. 原則として、手順3以降はPC操作を求めない。

### 1.3 成功の定義

- 普通のスキャン機能と競合せず、指定フォルダへ新規保存された適切な画像のみ処理する。
- 原稿の上・下・左・右のどこに黒い背景があっても、また四辺すべてにあっても、紙面を保全して取り除ける。
- 見開きは初期版では見開きのまま1枚のA4へ印刷する。
- 文字、挿絵、写真の黒を単純な色置換で消さない。
- 解析に失敗・不確実な場合は誤印刷するより**保留**を選ぶ。
- アプリを停止・再起動しても意図しない二重印刷を起こさない。

### 1.4 対象外（v1.0）

クラウド送信、オンラインAI画像認識、OCR全文検索、書籍のページめくり操作、中央綴じ目の影の完全除去、曲面ページの完全な幾何学補正、複数ページ自動分割、カラー印刷、両面印刷、自動裁断、スキャナードライバー自作、印刷機内ファームウェア変更、スマートフォン操作画面。

## 3. 提供サンプルの観察と技術的含意

### 3.1 サンプルの識別

- 管理用識別子：`SAMPLE-001`
- チャット添付名：`IMG_0001.jpg`
- サイズ：**1447 × 2048 ピクセル**、RGB / JPEG
- 当該添付ファイルのSHA-256：`20ed13fa505d5eae3949308390cb03a0513da4c1a308a974acd3a1171adf3cb3`
- このチャットで受け取ったファイルでは有効なDPIメタデータ・Exifが確認できない。
- 著作物を含む私的な資料であるため、**公開GitHubや公開テスト素材へは添付しない**。今後、元画像を自分の端末上でのみ使って検証する。

### 3.2 観察

- 紙面は見開き。文字・カラー図版・色付き背景があり、単純な「白い最大領域」だけでは紙面を取り切れない。
- **画像右側と下側に広い暗灰色の原稿台背景**がある。完全な黒（RGB 0,0,0）ではなく、グレーの明暗差やむらを含む。
- 紙面の端は完全な直線ではなく、本の湾曲と綴じ目の影がある。
- 画像そのものが通常の読書方向に対して横向きに見える。**暗い領域の除去と、正しい読み方向への回転は別の機能**として扱う。
- 画像の外枠には細い白色帯がある。このため、外周の1画素だけを背景探索の起点とするflood fillは不適切。
- 写真・図版・文字の暗い部分と、原稿台の暗い部分を画素値だけで区別することはできない。

### 3.3 ここから導く実装要件

- 外周の**帯状領域の複数箇所**を種にできる背景検出とし、最外周1画素だけに依存しない。
- 紙面候補は色の明るさ、境界、面積、局所的な質感、連結関係を併用する。
- 画像境界に紙面が接していても紙面を候補から除外しない。
- 見開き中央の暗い綴じ目を、背景扱いして穴抜きしない。
- 曲線になった本の外縁を無理に台形補正せず、まず紙面の保全を優先する。
- 紙面検出結果のマスク、境界、保留理由を保存して検証可能にする（マスク保存は開発・デバッグ用設定で可）。

## 4. システム構成

```text
Canon MF244dw
  │ 本体で「スキャン → PC」を操作
  ▼
Canon MF Scan Utility（既存・変更最小）
  │ JPEGを専用フォルダへ保存
  ▼
[INBOX：受信フォルダ]
  │ 新規ファイル監視 / 書き込み完了待ち / 初期ファイル除外
  ▼
[処理キュー / 重複防止状態DB]
  │
  ├─→ 検証失敗 → [HOLD：保留] → 通知 / 手動確認
  │
  ▼
[画像読み込み → 紙面検出 → 外側白化 → 回転・A4配置]
  │ 品質ゲート
  ├─→ 信頼できない → [HOLD：保留]
  │
  ▼

  │ Windows GDI + インストール済みCanonドライバー
  ▼
[Windows印刷スプーラー] → [Canon MF244dw]
  │
  ▼
[ジョブ記録：送信済み / 状態不明 / エラー]
```

## 6. 受信・監視の設計

### 6.1 専用受信フォルダ

- **原則**：MF Scan Utilityの「デバイスからスキャン」→スキャン種別の保存先を、アプリ専用 `inbox` に設定する。
- 通常の写真・文書の保存フォルダと分離する。
- `inbox`・出力先・一時フォルダを同じ場所にしない。出力ファイルを再検知してループさせない。
- 受信フォルダは任意設定可能。共有/同期フォルダ（OneDriveなど）は初期設定で避け、PCローカルを推奨。
- 日付サブフォルダ生成をOFFにする。ユーザー事情でOFFにできない場合、v1.0では自動追跡せず設定調整を促す。

### 6.2 受信対象の判定

- 監視をONにした時点の既存ファイルを基準集合として記録し、**ON以前からあるファイルは自動印刷しない**。
- ON後にファイル作成・移動・リネームが起きたら「候補」として取り込む。
- 拡張子と実際のファイルヘッダを検証。`jpg`/`jpeg`以外は「未対応」として保留・通知する。
- 監視中のOS再ログイン／アプリ再起動では、**中断中・不明状態のジョブを勝手に再送信しない**。
- 画像と関係ないドキュメントを置いても印刷しない。**ただし、専用フォルダに他のJPEGを手動コピーした場合、それをCanonスキャンと完全に区別する認証機構はないため、印刷候補になり得る。** これを防ぐ運用条件は「専用フォルダへ他の画像を置かない」こと。必要ならCanonのファイル命名規則を追加の緩いフィルタとして検討するが、規則が保証されない限り絶対条件にはしない。
- ユーザーが意図して同じ紙面を再スキャンした場合は、**別の新規到着として印刷を許可**する。「同一画像ハッシュなら永遠に印刷しない」という仕様にはしない。

### 6.3 ファイル保存完了の判定

1. 作成イベントを受信。イベント重複は同じ候補に集約。
2. ファイルのサイズ・最終更新時刻が連続した観察期間で変わらないことを確認（初期値の例：1秒間隔、2回）。
3. ファイルを読み取り専用で開き、JPEGのデコードが成功することを確認。
4. 不完全なファイルは一定時間（初期例：60秒）まで待ち、超過したら保留。
5. 同時処理は原則1ジョブ。次のスキャンはキューで待つ。

*数値は仮置き。データ保存速度やネットワーク環境に合わせ、実測で確定する。*

### 6.4 ON/OFFの意味

- `OFF`：新しい画像を自動印刷対象にしない。Canonの普通のスキャンには干渉しない。
- `ON`：以降の対象フォルダへの新規到着を自動処理する。
- 処理中にOFF：新規受付を止め、**まだ印刷送信していないジョブは原則保留**。既にスプーラーに送信済みのジョブを勝手にキャンセルしない。
- クラッシュ後：前回未完了だった案件は「要確認」とし、明示操作がない限り自動で再送信しない。

## 7. 画像処理・ページ自動検出の設計

### 7.1 最重要原則

**黒を白に塗り替えるのではなく、原稿台の背景と紙面の領域を分ける。** 内部にある黒文字・挿絵・写真・綴じ目は紙面として保全する。

### 7.2 処理ステージ

| 段階 | 処理 | 注意 |
|---|---|---|
| IP-01 | 原画を複製し、ピクセル形式とメタデータを検証 | 元画像は変更しない |
| IP-02 | EXIF方向が有効なら正規化。無ければ既定方向を保持 | 内容から勝手に90度回さない |
| IP-03 | 検出用に縮小画像・輝度/彩度・エッジ情報を作る | 最終出力は元画像の解像度を活用 |
| IP-04 | 外側の暗い領域・紙面候補を複数の方法で抽出 | 固定しきい値のみ不可 |
| IP-05 | 紙面領域の連続性、外形、エッジ、周囲との差を照合 | 最大の明領域だけで決めない |
| IP-06 | 紙面境界（マスク）を確定 | 上下左右の部分欠けを許容しない |
| IP-07 | 境界の外側だけ白色へ置換 | 内側の画素は保持 |
| IP-08 | 必要最小限の切り抜き・軽い傾き補正 | 曲面の強引な平坦化はしない |
| IP-09 | A4レイアウト | 文字欠け・プリンタ余白・拡大率を制御 |
| IP-10 | 品質ゲート | 不確実なら印刷せず保留 |

### 7.3 背景検出の候補手法（実装上の提案）

- **候補A：周囲の暗い領域のモデル化。** 画像外周から数%内側までの複数ポイントをサンプリングして、暗い領域の輝度分布・質感を推定する。狭い白枠や反射を跨いで暗背景候補を探せるようにする。
- **候補B：紙面・背景の境界検出。** Sobel/Canny等の勾配に加え、紙の明度、近隣の色・質感差を考慮する。
- **候補C：領域連結と形状検査。** 外側の広い背景領域と内側の書籍領域を分離し、紙面として自然な大きさ・連続性を持つものを採用する。
- **候補D：輪郭補完。** 紙が画像の外枠に接する場合、途中まで見える境界や隣接位置から不足部分を保守的に推定する。

**固定の「RGB 100未満を削除」や「最大の白領域だけ採用」にはしない。** 実装はA/B/Cの組合せを優先し、サンプルで実証する。画像解析に使うOpenCV関数の選定は設計指針であり、実測前に特定のアルゴリズムを唯一の正解として固定しない。

### 7.4 上下左右全面の黒背景

- 背景は一辺だけ・二辺・三辺・四辺すべて・四隅に分離して存在する可能性を扱う。
- 黒ではなく濃灰・明暗むら・反射を含む。
- 外縁に狭い白枠が存在しても、暗背景検出に失敗しないようにする。
- 原稿が枠に接触しているときは、欠けた側を強引に切りそろえない。
- 原稿外周の暗い影と紙内部の黒図版が連続するときは、過剰削除を回避するか保留する。

### 7.5 ページ形状と綴じ目

- **見開きは1つの出力対象**。真ん中の黒い綴じ目の影は紙面内部として残す。
- 曲がった紙の輪郭は、多角形/滑らかな輪郭として保持可能な構造にする。初期版では直線・四角形へ無理に矯正しない。
- 紙面外の暗い部分を切り取って白化できれば十分であり、台形補正・湾曲補正は後から検討する。
- **紙面の縁の文字や図版を削らない**ように、検出した輪郭から内側へ追い込む補正（安全性のない負のマージン）は禁止する。
- 軽い傾きの補正は、補正後に内容が収まる白いキャンバスを確保できる場合に限る。

### 7.6 方向・回転

- スキャン画像の向きと読書方向は一致しないことがある。`SAMPLE-001`が該当。
- 初期版の方針は **「回転0°（なし）を既定、設定で90°／180°／270°を選択可能」** とする。
- EXIFに方向指定があれば反映する。ただしチャット添付のサンプルにはEXIFがない。
- 縦横比から印刷用紙の縦置き／横置きを選ぶことと、文章の上下を正しくすることは異なる。OCR無しで自動判定したとは扱わない。
- **おすすめ運用**：初回の試し刷りで、同じ向きに本を置く運用なら固定回転設定を確定する。

### 7.7 品質ゲート（自動印刷してよいか）

以下を組み合わせた判定を必須とする。判定の数値閾値はテスト画像で調整し、初期値を仕様上の確定値と誤認しない。

1. 紙面らしい連続領域が検出できた。
2. 紙面面積が極端に小さい／大きい、または境界が不自然ではない。
3. 切り出し候補に内容の欠落を示唆する高密度の文字・エッジがない。
4. 背景候補と紙面候補の境界に十分な根拠がある。
5. 元画像のデコード、A4配置、保存が成功する。
6. 必要に応じて画像診断ログに「背景マスク」「紙面境界」を記録できる。

状態は `ACCEPT`（自動印刷可能）または `HOLD`（要確認）の二値を最低限持つ。定量的な信頼度スコアは開発中の補助値であり、未検証の数値だけで自動印刷を解禁しない。

### 7.8 何もしない方が安全な入力

すでに余白が白く黒背景がない場合は、明確な紙面領域が検出されなければ**不必要に切り抜かず**、A4への配置を優先できる設計とする。ただし、暗色の紙や全面黒写真など背景と区別が困難な入力は、無加工で黙って印刷するより保留を優先する。

## 8. A4組版・印刷仕様

### 8.1 用紙と印刷条件

| 設定 | 初期値 |
|---|---|
| 印刷先 | Windowsで選択した「Canon MF244dw」に対応するプリンターキュー |
| 用紙 | A4、210×297mm |
| 方向 | 紙面の縦横比によりA4縦/横を自動選択（文章の読書方向は別管理） |
| 色 | グレースケールで印刷（機器はモノクロレーザー） |
| 片面/両面 | 片面固定 |
| 部数 | 1部固定 |
| 内部品質 | 印刷用ラスタは300dpiを初期目安 |
| メーカー公表の非印字余白 | 各辺5mm [R4] |
| 配置 | A4の印刷可能領域に収め、中央配置 |
| 拡大 | **初期は拡大しない**。大きい場合は縮小 |

300dpiのA4全面は概算 `2480×3508 px`、各辺5mmは約59px。実際の印刷DCが返す物理オフセット・印刷可能幅/高さを優先し、上記値を固定ハードコードしない。

### 8.2 原寸大の扱い

- **重要**：物理サイズを正確に再現するには、スキャン時DPIや印字スケールが確かである必要がある。
- 画像ファイルに信頼できるDPIがある場合はそれを用いる。
- DPIがない場合はMF Scan Utilityの既定設定300dpiを初期推定値として使えるが、**原寸を保証しない**。初回キャリブレーションで定規入りの紙などを読み、倍率を確認する。
- 「印刷可能領域を超える場合のみ縮小」が初期動作。拡大してA4全面を使うオプションは将来追加可能。

### 8.3 印刷APIの原則

- Windowsの印刷キューおよびインストール済みCanonプリンタードライバーを使用する。
- 画像をGDIの描画処理で出力する方式を第一候補とする。MF244dwに対しJPEGバイト列をそのまま`RAW`で送る実装は採用しない。RAWはプリンター側のページ記述言語に依存し、この要件とは合わない。
- Windowsの `DEVMODE` 相当の設定でA4、片面、1部、方向等を指定する。ドライバーによって無視・変更される可能性があるため、実機テストで確定する。
- Windowsの `GetDeviceCaps` 相当から印字可能領域と物理オフセットを取得し、二重の拡大縮小や印字欠けを防ぐ。
- 印刷ジョブ送信が成功しても、**排紙完了を確認したことにはしない**。スプーラーの受付と実際の排紙を明確に分ける。

### 8.4 自動印刷の安全条件

`監視ON` かつ `対象の新規ファイル` かつ `品質ゲートACCEPT` かつ `印刷先設定済み` の4条件を満たす場合のみジョブを送信する。OFF、保留、不明なプリンタキュー、初期テスト未通過の場合は送らない。

## 9. 処理状態・障害時動作

### 9.1 状態遷移

```text
NEW → STABILIZING → QUEUED → PROCESSING → QUALITY_CHECK
  │         │            │          │              ├── HOLD
  │         │            │          │              └── READY
  │         │            │          │                    │
  │         │            │          └─ERROR/HOLD         ▼
  │         │            └─CANCELLED/HOLD        SUBMITTING
  │         └─TIMEOUT/HOLD                             │
  └─IGNORED                                       ┌─────┴─────┐
                                               SUBMITTED  UNKNOWN/HOLD
```

- `SUBMITTED`：Windows印刷スプーラーが送信を受け付けた、という意味。物理的な排紙成功を意味しない。
- `UNKNOWN/HOLD`：送信中のクラッシュや通信断など、同じジョブの受付有無を判断できない状態。**自動再送信禁止**。
- `HOLD`：元画像・加工画像・原因を保持し、手動確認を待つ。
- `IGNORED`：監視ON前から存在したファイル、対応外の入力など。

### 9.2 二重印刷防止

- 受信1件に一意の `job_id` を発行する。
- 取り込み元のファイル識別（パス・生成時刻・サイズ・内容ハッシュなど）を記録し、同じ作成イベントを重複登録しない。
- **内容ハッシュ単独を永続的な重複除外キーにしない**。同一ページの再スキャンを正しく別ジョブとして扱う必要がある。
- 印刷送信直前に「送信開始予定」を永続化し、成功時にWindowsのジョブ番号・時刻を記録する。
- プロセス停止直後の不明ジョブを無条件で再送信しない。
- 一度送ったジョブの再印刷は「履歴から明示的に再印刷」でのみ可能とする。

### 9.3 エラー別の扱い

| 状況 | 動作 |
|---|---|
| 画像の書込が完了しない | タイムアウト後HOLD |
| 画像が壊れている | HOLD、原画保全 |
| 紙面検出に十分な確信がない | HOLD、境界プレビューを残す |
| 本の縁で文字が切れそう | HOLD |
| プリンターが未設定・見つからない | HOLD |
| 用紙切れ、オフライン、印刷キュー停止 | 状態取得可能なら通知。自動で再度別ジョブを送らない |
| 印刷ジョブ送信中にアプリが落ちる | UNKNOWN/HOLD、明示確認まで再送信しない |
| 同じファイルのイベントが2回届く | 1ジョブに集約 |
| アプリが再起動する | 以前の保留案件を勝手に再送信しない |
| 監視フォルダが消えた/アクセス不可 | 監視停止とエラー通知 |

画像のしきい値・面積・輪郭の複雑なパラメータは通常画面に出さず、必要なら開発者設定に限定。

### 11.1 ディレクトリ例（実際の場所は初期設定で確定）

```text
%USERPROFILE%\Documents\KuroCutPrint\
```

### 11.3 フォルダ監視の安全

- 規定の受信フォルダ以外を勝手に再帰監視しない。
- 管理者権限を不要にし、Windowsの通常ユーザーとして動く。
- シンボリックリンクや異常パス、極端に巨大な画像、展開時の過大メモリ消費を制限する。
- 本人が選んだプリンター以外へ印刷しない。

## 13. 技術スタックと方針

| 層 | 第一候補 | 理由・注記 |
|---|---|---|
| 実行環境 | Python 3.13 / Windows 11 | 個人用、ローカル常駐。実装開始時に依存ライブラリの互換版を固定 |
| 画像処理 | OpenCV + NumPy + Pillow | 紙面検出、外側白化、画像変換 |
| フォルダ監視 | watchdog | Windowsファイルシステムのイベント駆動 |
| 印刷 | pywin32 + Windows GDI | 導入済みプリンタードライバー経由で描画 |
| UI | Tkinter + （必要なら）pystray | 小さな設定画面・タスクトレイ |
| ログ | Python logging + SQLite | 失敗調査、二重送信防止、履歴 |
| 配布 | PyInstaller | ローカルのPython環境なしでも起動できるEXEを目標 |

- Pythonパッケージの具体的バージョン、pystrayとTkinterのスレッド連携、DPI/印刷DC、EXE化後の動作は**M2～M3の検証対象**。
- 印刷ダイアログが勝手に開くWindowsの画像ビューアー経由の `ShellExecute('print')` は、無人印刷の安定性に懸念があるため第一候補から外す。
- 単一ユーザー用のため、Webサーバー、ユーザー認証、遠隔API、データベースサーバーは作らない。
- 常駐中のCPUを消費しないイベント駆動・アイドル負荷最小を優先する。

```python
        hold(job, "MONITOR_STOPPED_BEFORE_SUBMISSION")
        return
    persist_before_print(job, state="SUBMITTING")
    try:
        spool_id = submit_via_installed_windows_driver(a4_file)
        persist_after_print(job, state="SUBMITTED", spool_id=spool_id)
    except IndeterminateSubmission:
        hold(job, "PRINT_SUBMISSION_UNKNOWN")  # 自動再送信しない
    except Exception as error:
        hold(job, "PRINT_ERROR", detail=error)
```

## 14. 初期導入ガイド（実装後に利用者が行う作業）

1. Canon MF Scan Utilityの「デバイスからスキャン」で、通常用とは別の「カスタム1」などを選択する。
2. **カラー・300dpi・JPEG**を基本設定とする。白黒2値PDFではグレーの情報が失われ得るため、初期版には不向き。
3. 専用 `inbox` を保存先に指定し、日付フォルダ作成とスキャン結果の確認画面をOFFにする。
4. スキャン後の処理を「アプリケーションを起動しない」にする。
5. MF244dw本体からその設定で1回スキャンし、期待した画像が受信フォルダへ保存されることを確認。
6. アプリで受信フォルダとWindows印刷キューを選択。
7. `SAMPLE-001`などで背景除去結果をプレビューし、必要なら固定回転を設定。
8. 手動の試し刷りを1枚行い、方向・文字欠け・余白・部数を確認。
9. 確認できたら監視ON。以後は本体のスキャン操作のみで運用する。

注：これは実装後の導入手順案であり、現在すべての設定がユーザーのPC上で完了しているという意味ではない。

## 15. 開発段階・完了の区別

| 段階 | 内容 | 完了判断 |
|---|---|---|
| M0：スキャン受信条件の確認 | フォルダ、形式、実際の元画像、印刷キューを記録 | 実機の設定と受信例を確認 |

| M2：印刷接続 | 処理済み画像を実機にA4・片面・1部送信 | 紙の排出を含む実機確認 |

## 16. リスクと回避策

| リスク | 重要度 | 回避方針 |
|---|---|---|
| 暗い図版を背景と誤認して消す | 高 | 画素値のみで判断しない、紙面領域内は保全、低確度は保留 |
| ページの端の文字を切る | 高 | 安全な輪郭余白、内容欠落検査、保留 |
| 無人印刷で紙とトナーを浪費 | 高 | 専用フォルダ、監視ON制御、品質ゲート、部数1、重複防止 |
| Windowsの印刷ジョブが二重送信される | 高 | 永続ジョブ状態、曖昧な送信結果の再送禁止 |
| ドライバーと用紙サイズ指定の食い違い | 中 | 実機試し刷り、印刷DCの実サイズ参照 |
| 横向き原稿が横向きに出る | 中 | 初回キャリブレーション、固定回転設定 |
| DPI情報がなく倍率がずれる | 中 | スキャン条件参照、原寸保証は較正後 |
| PCがスリープしてスキャンを受け取れない | 中 | OS/電源設定案内、PCスリープ中は保証外 |
| 元画像が同期フォルダへ送られる | 中 | ローカル保存を初期推奨 |
| 書籍画像がパブリックGitHubに露出する | 高 | 公開テスト素材へ入れない。合成素材だけ共有 |
