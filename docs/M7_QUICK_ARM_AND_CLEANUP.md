# APP-033｜直接許可と印刷後の原稿自動整理（v0.7.2-rc.1）

作業日：2026-11-22 JST。対象：自分専用のコピー代替アプリ、Windows 11 + Canon MF244dw。

## 決定 ADR-010：ユーザーの明示許可があれば手動試し刷りをスキップ可能

- 新しい案内：**①1枚試し刷り → ②紙の結果確認 → ③自動印刷許可 → ④監視開始**、または**③直接許可 → ④監視開始**。
- ③はプリンターキューを選択済み、監視停止中、別の印刷や再加工が進行していない場合に押せる。
- 実紙検証がないときは「**試し刷りを省略・印刷品質未検証**」を説明した確認ダイアログを表示。利用者が「はい」を選んだ場合だけ、その起動中の該当キューへの自動印刷を許可する。
- すでに①②を終えた場合は従来の確認済み経路を利用できる。実機検収済みと明示許可での省略は画面上も区別する。
- 監視開始前から存在したJPEGは、どちらの許可経路でも自動処理・印刷しない。
- **明示許可は起動時に復元しない。** 監視停止・印刷先変更・回転/DPI/A4配置/内側カット量変更・失敗では許可を解除する。稼働中にプリンター選択を変更できない。

## 決定 ADR-011：元JPEGは印刷完了が確認できたときだけごみ箱へ（既定ON）

- GUIに**「印刷完了を確認できた元JPEGを、ごみ箱へ移す」**チェックボックスを設置し、既定はON。ユーザーはOFFを選べる。
- 「コピー」の運用を意図するため、**受信フォルダ直下に新しく届いたJPEG**だけを対象にする。既存ファイル、フォルダ外のファイル、旧履歴、手動試し刷りの画像、加工済みA4プレビューや診断画像は削除対象外。
- `StartDoc/EndDoc`が成功しても、データが**印刷キューへ送信された**だけなので元ファイルを削除しない。`SUBMITTED`やジョブ消失だけでは削除しない。
- Windows印刷キューが対象ジョブについて明確に`JOB_STATUS_PRINTED`を返し、監視停止前で、元JPEGのファイルID代替となるサイズ・更新/作成時刻の指紋が一致し、パスが安全な指定受信フォルダ直下だった場合だけ`Send2Trash`で**ごみ箱へ移動**。元画像を完全消去しないので、誤判定に備えて復元が可能。
- 印刷完了をキューから確認できないドライバー、キューから即座に消えたジョブ、エラー、タイムアウト、JPEGの上書き/差し替え、削除権限エラーでは**画像を残す**。Driverごとにステータス通知が異なり、実機で自動整理の成否を確認する必要がある。
- 完了判定は**Windows印刷スプーラーの報告**であり、Canonの排紙センサーに直接接続するものではない。物理的な排紙成功と同義ではない。
- このアプリの中で新しく印刷送信したジョブだけを対象とし、再起動後に昔の印刷履歴を根拠として元JPEGを消すことはない。途中停止時も自動整理しない。
- ごみ箱へ移した後もSQLiteのジョブ情報と加工済み画像はローカルに残し、印刷の履歴と問題の原因を辿れる。受信ファイルがもう存在しない場合、その原稿を再加工するにはごみ箱から戻すか再スキャンが必要。
- バッチ更新では元スキャンのファイルを削除しない。設定保存にはごみ箱チェックのON/OFFだけを記録する。

## 操作例

1. Canonの保存形式をJPEGにし、「日付別フォルダ」をOFF。アプリの専用受信フォルダを指定。
2. Windows側のMF240 Seriesキューがオンラインになっていることを確認。内側カットはまず0〜2mm。
3. GUIの「印刷完了を確認できた元JPEGを、ごみ箱へ移す」が**チェック付き（既定）**なのを確認。原稿を残したいときはOFF。
4. 実紙確認を省略したい場合は**③自動印刷を許可**を押し、「試し刷り・紙確認を省略して進む」確認画面で「はい」。その後**④監視開始（自動印刷）**を押す。
5. Canon本体から新たにスキャンする。アプリが自動加工し、Windowsの印刷キューへ送信する。
6. 正常に印刷されても、印刷キューが`PRINTED`を通知しないときは元JPEGを残す。これは失敗ではなく安全な保留。必要なら受信フォルダで手動整理する。
7. 運用を終えるときは「監視を停止（準備へ戻る）」。再度無人印刷するには③の明示許可が必要。
